# requirements.txt — THE LIST A PERSON EDITS. The image does not install this file.
#
# Every direct dependency is pinned to ONE exact version here, with the reason it is in
# the list. `requirements.lock` is generated from this file and pins every package the
# app needs, transitive ones included, each with its hashes; the Dockerfile installs
# ONLY the lock, in hash-checking mode. So the versions the test suite passed on are the
# versions that deploy (tests/test_django_lts.py fails if the lock is stale, if anything
# here is unpinned, or if the environment running the tests is not the lock).
#
# Why: this file used to carry `daphne>=4.0.0`, `openai>=1.0.0`, `firebase-admin>=6.0.0`
# and two bare names, nothing pinned the transitive packages, and the Dockerfile ran a
# second unpinned `pip install daphne` — so every `fly deploy` installed whatever was
# newest that day (production-readiness audit, 2026-09-26).
#
# TO CHANGE A VERSION (or add or remove a package):
#   1. Edit the pin below.
#   2. Regenerate the lock. It is a UNIVERSAL resolution (one file that installs on the
#      macOS dev machines and on the linux image alike), which is why it uses uv:
#          pip install uv        # once, anywhere; it is a tool, not a dependency
#          uv pip compile requirements.txt --universal --python-version 3.12 \
#              --generate-hashes --no-annotate --output-file requirements.lock \
#              --custom-compile-command "see the header of requirements.txt"
#      Add `--upgrade-package <name>` to move one transitive package to its newest
#      version that the pins allow; `--upgrade` moves them all.
#   3. Install it where the tests run:
#          .venv/bin/pip install --require-hashes -r requirements.lock
#   4. Run the gate (CLAUDE.md), and commit requirements.txt and requirements.lock
#      together.
#
# NOTE: pytest, pytest-django, coverage and flake8 are KEPT — they are used by
# the regression gate (pytest.ini + tests/) and by CI.
# Removed as unreferenced: certifi, django-extensions, factory-boy, isort, pytz, setuptools, urllib3

# PDF receipts (subscription/receipts.py). Every confirmed payment has a receipt, and
# Arabic is the primary language it is written in — which takes three pieces, not one:
#   fpdf2           the document itself. Pure Python, ~240 KB, no system libraries
#                   (WeasyPrint needs cairo + pango in the image, reportlab is a much
#                   larger C extension), and it embeds and subsets a TrueType font.
#   arabic-reshaper letter joining forms. Without it the PDF shows detached letters.
#   python-bidi     the Unicode bidirectional algorithm, so a mixed line such as
#                   "Premium · 30 يوماً" comes out in the order a reader expects.
# The font is Noto Naskh Arabic, in subscription/fonts/ under the OFL — see the module
# docstring for why the app's own brand font cannot render this document.
fpdf2==2.8.8
arabic-reshaper==3.0.1
python-bidi==0.6.11
