# Backend bugs found while building the app

A shared notebook between two sessions.

- **The app session** (works in `yalla_gym/`) adds rows while wiring screens to the real
  API. It fills: ID, Severity, Where, What happens, What the app does meanwhile. It never
  edits the last two columns and never edits backend code.
- **The backend session** reads this file, fixes, and fills **Status** and **Backend note**
  (commit, or why not). It does not edit the other columns; if a row is wrong, say so in the
  note and set `invalid`.

Status values: `open` · `in progress` · `fixed` (give the commit) · `wontfix` · `invalid` ·
`needs owner` (a decision is owed first).
Severity: **P0** breaks a Phase 1 flow or leaks data · **P1** visible to users, has a client
workaround · **P2** wrong but harmless today.

Every row was read from the code (file:line at commit `af6bf00` + working tree of
2026-09-19) and, from B-020 on, reproduced from the app. Missing features the designs need
are not bugs: they are in `BACKEND_DELTA.md` and `yalla_gym/app/PLAN.md` §8.

### New server rules the app must handle

- **A new `code` on an old refusal.** A refusal that answered only its status default
  (`bad_request`, `not_found`, `conflict`, `permission_denied`) may gain its own code
  (API_CONTRACT.md §6). Treat an unknown code as its status default and nothing breaks.
- **Pay may answer `409 price_changed` without a quote mismatch** when the subscription
  moved plan during the call: show `expected_amount` and ask again.
- **`more_calories`** is a swap tag the design does not draw: the offer is a bigger portion.

### New server rules the app must handle (owner's decisions, not bugs)

- **Frozen coaching:** training writes on a routine whose coaching is unpaid or over answer
  403 `coaching_frozen`, `coaching_unpaid` or `coaching_ended` with `trainer_id`; the routine
  stays readable. `GET /api/v1/coaching/current/` shows `status: frozen`, `frozen_since`,
  `renewal_reminder` (3 days before a month ends); `payment_due` is no longer sent.
- **Lapsed plan:** diet plans stay readable, every use answers `no_entitlement`;
  `subscriptions/current/` has `access` (`active`, `frozen`, `inactive`) and `renewal_due`.
- **Pushes:** `coaching_renewal_soon`, `coaching_payment_due` (now "paused"),
  `subscription_expiring`, `subscription_expired`.
- **Templates:** `templates/{id}/generate/` takes `client_ids` (several clients, one private
  copy each) or `assign: false` (a draft to edit, then `assign_to_client`).
- **Trainer account:** deleting it answers 409 `trainer_has_active_clients` while any client
  is coached.
